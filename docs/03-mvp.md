# 03. MVP: запуск и деплой

## Что это
Статический сайт в `app/` (HTML + JS, без сборки и зависимостей). Данные пользователя — в `localStorage` браузера. Контент — `app/data/content.json` (вручную), ресурсы — `app/data/resources.json` (генерируется из `data/*.yaml`).

## Что умеет
- **Профили** (несколько на одном устройстве): модуль, цели, текущие band по навыкам, часы в неделю, дата теста.
- **Сегодня**: задания на день по алгоритму из `docs/01` (веса навыков, фаза, неделя, журнал ошибок), чекбоксы, таймер, ссылки на ресурсы. Дневной план кэшируется (не меняется в течение дня); «Пересоздать» — перегенерировать.
- **План**: неделя/фаза, распределение часов по навыкам, фазы с датами, ближайшие 7 дней.
- **Карточки**: SRS (упрощённый SM-2), стартовый набор из 54 chunks, добавление и импорт CSV (`front;back`).
- **Ошибки**: журнал с тегами; топ тегов влияет на следующие задания.
- **Проверка**: генератор промпта для оценки Writing/Speaking в любом ИИ + сохранение оценок.
- **Прогресс**: моки (overall по правилу IELTS), приблизительный raw→band, выполнение по неделям.
- **Ресурсы**: фильтр по навыкам; рискованные (`ru_risk`) скрыты по умолчанию.
- **Настройки**: экспорт/импорт JSON-бэкапа.

## Локальный запуск
```bash
npm start            # = python3 -m http.server 8080 -d app  → http://localhost:8080
npm test             # тесты движка (Node ≥ 20)
npm run data         # пересобрать app/data/resources.json (нужен pyyaml)
```
Открывать через http-сервер, не через `file://` (fetch для JSON).

## Деплой
**GitHub Pages:** запушь в `main` → Settings → Pages → Source: *GitHub Actions*. Workflow `.github/workflows/pages.yml` прогонит тесты и опубликует `app/`.
**Vercel:** Import repo → Framework: *Other* → Root Directory: `app` → Build command: пусто → Output: `.`.

> Не коммить экспортированные профили (они в `.gitignore`).

## Ограничения MVP (осознанно)
- Нет аккаунтов и синхронизации между устройствами → экспорт/импорт JSON. Следующий шаг по `docs/01`: Supabase Auth + таблицы.
- Нет аудио-записи и API-вызовов ИИ: проверка — через копирование промпта.
- Нет Telegram-бота.
- Raw→band таблицы приблизительные; для точной оценки используй таблицу конкретного теста.
- Стартовый набор карточек мал (54): для словарей NGSL/NAWL/AVL используй импорт CSV (проверь лицензии списков).
- Часть ресурсов не проверена (`status`): прогони `python3 scripts/check_links.py`, затем руками обнови статусы.

## Как добавлять контент
- Новый ресурс → `data/resources_extra.yaml` (или `resources.yaml`) → `npm run data`.
- Темы/вопросы/карточки → `app/data/content.json`.
- Чтобы ресурс попал в ежедневные задания, добавь его `id` в `resourceMap` в `content.json`.

## Аккаунты и облако (v2)
Вход — Supabase Auth (email + пароль). Данные профиля — одна JSON-строка в `public.ielts_user_data` (RLS: пользователь видит только свою). Клиент: `app/vendor/supabase.js` (UMD, локально), настройки — `app/js/cloud.js` (URL и anon-ключ публичные по дизайну). Для своего деплоя создай проект Supabase, выполни SQL таблицы и подставь URL/ключ. Локальный кэш: `localStorage` (`ielts_v2_<user id>`), при отсутствии сети изменения отправятся позже.
